# annai napkin

## Toolchain (high)
- Zig 0.16.0 comes from zig2nix (`zig2nix.outputs.packages.<sys>.zig-0_16_0`), pinned in flake.nix. nixpkgs' zig_0_15 and zig2nix's 0.15.2 do not link on current macOS (undefined libc symbols); 0.16.0 does.
- Zig 0.16 std: no file API outside `std.Io` (`main(init: std.process.Init)`, `std.Io.Dir.cwd().readFileAlloc(init.io, ...)`), no `std.posix.socket/bind/kevent/write`, no `std.time.milliTimestamp`, no `std.BoundedArray`, no `ArrayList.writer()`. Sockets go through `std.posix.system.*` (libc on macOS, raw syscalls on musl; `posix.errno(rc)` works for both), `posix.setsockopt`/`posix.read`/`posix.poll` still exist, the clock is `system.clock_gettime(CLOCK.MONOTONIC)`. `posix.IPV6` is `void` on darwin: server.zig hardcodes IPV6_V6ONLY = 27 there. The event loop stays on src/poll.zig (ADR 0001, owner decision 2026-10-18); `std.Io` is only for blocking file reads.
- Cross-compile locally before pushing: `nix develop -c zig build -Dtarget=x86_64-linux-musl` catches Linux-only std differences (SOCK flags, accept4) in seconds.
- `build.zig.zon2json-lock` is written by hand: `zig2nix zon2lock` crashed here. Recipe for a new dependency: in a scratch dir, `touch build.zig && zig fetch --global-cache-dir ./gc <url>`, then the lock key is the Zig hash and `hash` is `nix hash path --mode flat gc/p/<zighash>.tar.gz`.
- A stale `~/.cache/zig/p/<hash>.tar.gz` gives "hash mismatch" in the devShell: delete it.
- The flake `src` fileset only sees git-tracked files: `git add` a new source or corpus file before `nix flake check`, or the sandbox build fails with `FileNotFound` while the devShell passes.
- No import-from-derivation allowed: the orchestrator evaluates Linux checks with `--eval-store auto --store ssh-ng://...`. zig2nix's `package` does IFD for `fromZON`, `target` and `deriveLockFile`: flake.nix passes pname, version (regex on build.zig.zon), zigTarget, a non-existent `zigBuildZonLock`, and links its own deps linkFarm in `preBuild`. Verify with `nix flake check --all-systems --no-build --option allow-import-from-derivation false`. Recheck after any zig2nix bump. After a source change, run plain `nix flake check` (or `nix build`) first: `--no-build` fails with `path '...-source' is not valid` until the `src` fileset is in the store.
- `zig build test` ends with only "failed command" and no summary when a test floods stderr (one log line per iteration of a 1024-loop): gate server logs that tests trigger in bulk with `if (!builtin.is_test)`. Run the test binary under `.zig-cache/o/*/test` directly to see the real result.
- `nix fmt` (nixfmt-tree) formats in place; run it before `git add`, it rewrites long lines in test scripts.

## TOML (high)
- microwave @9b9c69b (ADR 0003). Fails on a value at EOF without trailing newline: `parse` in src/config.zig appends "\n".
- Tables come back as `.table`, `.inline_table` or `.implicit_table` (dotted keys): always `anyTableOrNull`/`anyArrayOrNull`.

## Schema choices not spelled out in the ADRs (medium)
- annai.toml: `mode`, `listen` (`addr:port`, port required), `zones` (paths, relative to annai.toml), `[forwarding] upstreams` (bare IPs, port 53, uchi only, optional: absent = REFUSED outside the zones) + `min_ttl` (0), `max_ttl` (86400), `cache_bytes` (16 MiB), `[update]` (soto only): `[[update.keys]] name, secret_file` (absolute path; `keys` required), `max_ttl` (120, cap on a dynamic record's TTL), `lifetime` (3600 s a dynamic record stays whatever its TTL). Unknown keys are errors everywhere.
- Key file (`secret_file`): one line, `<base64 secret>` or hanko's `<name>:<base64 secret>` (the name must be this key's; trailing dot and case ignored). Read only by `serve`; `annai check` sees the path, not the file (secrets do not exist at build time). The module renders `secret_file = /run/credentials/annai.service/tsig-<name>` and sets `LoadCredential=tsig-<name>:<secretFile>`, so a root-only sops file works with `DynamicUser`.
- CAA (RFC 8659): `caa = [{ flags = 0, tag = "issue", value = "letsencrypt.org" }]`, tag 1-15 alphanumerics, flags u8; served opaquely.
- Cache TTL (ADR 0008): positive = min answer TTL clamped to [min_ttl, max_ttl]; negative = min(SOA TTL, SOA MINIMUM, max_ttl), min_ttl does not raise it, no SOA = not cached; other rcodes never cached. Every RR of a cached answer is served with the entry's remaining lifetime. Cap is in bytes (packet + key + 128 overhead), not entries: it is the memory bound.
- Reverse zones (ADR 0005): module options `reverse.zone` + `reverse.prefixes`, generated in nix/reverse.nix at render time (not as a `zones` default: that recurses). PTR only for owners `<node>.kekkai.<zone>`; SOA/NS/TTL/serial copied from the forward zone; prefixes on octet/nibble boundaries (no RFC 2317).
- Resolver modules: ADR 0002 ("clients point all their queries at it") + M2 decide the default route: unconditional, no flag. NixOS: `~.` routing domain + `default-route true`; darwin: `networking.dns = [ address ]` plus the existing `/etc/resolver/<domain>`.
- Zones: NS only at the apex (no delegation, ADR 0004); in-zone NS targets need A/AAAA; labels `[a-z0-9_-]`; wildcards rejected until M4; no per-RRset TTL (the zone `ttl` applies to every RRset including the SOA). TXT values longer than 255 bytes are split into 255-byte character-strings.
- Module: `zones.<origin>` attrsets (origin = attribute name); upstreams default Quad9 in uchi mode, rendered whenever non-empty so a soto config with upstreams fails `annai check`. No `openFirewall` option: ports are a deployment value (kekkai per-peer firewall, ADR 0010); the nixosTest opens 53 itself.

## Wire codec (high)
- src/wire.zig: `Message.parse(arena, packet)` borrows the packet; names and the RDATA of NS/CNAME/SOA/PTR/MX/SRV are decompressed into the arena (`layout`), everything else is opaque (RFC 3597). `Message.encode(buf)` / `Writer` compress owners and the RDATA names of those types except SRV (RFC 3597 §4); a question or RR that does not fit is rolled back (`error.NoSpace`).
- Pointers must point strictly before themselves; label types 0x40/0x80 and names over 255 bytes are `error.Malformed`. A header whose counts cannot fit the packet is refused before any allocation.
- Corpora live in `src/corpus/*.txt`, one `name = hex` packet per line, read with `@embedFile` (so they must stay under src/). Add fuzzer findings (M4) there.

## Engine and server (high)
- src/zone.zig: names are lowercase wire names; `Zone.names` holds every owner plus its ancestors as empty `Name`s (ENT = exists, no RRset = NODATA). `zone.find` = longest origin suffix at a label boundary. config.loadZone builds zones (validation and loading are one pass).
- src/engine.zig `respond(arena, ctx: Context, packet, out, transport, forward)`; `Context` = zones + (soto) TSIG keys, `*update.Overlay`, `now` (unix s, TSIG) and `mono` (monotonic s, overlay). FORMERR keeps the id and opcode but no question; EDNS errors are FORMERR, version != 0 is BADVERS; UDP limit = clamp(payload, 512, 1232), no OPT = 512, TCP = 65535; the OPT's 11 bytes are reserved so it survives truncation; TC is set when the question, an answer RR or the authority SOA does not fit; additional section is never filled (no glue for MX/SRV/NS targets yet). CNAME chase stops at the zone edge or after 8 hops; the final rcode is the last name's (dangling in-zone target = NXDOMAIN + SOA). ANY = HINFO "RFC8482" if the name exists else NXDOMAIN. Class != IN = REFUSED. RA = 1 only with forwarding (uchi); soto echoes RD and never sets RA. Opcode 5 = `update.apply` (uchi: REFUSED), other opcodes NOTIMP. `wire.Rcode` is non-exhaustive (upstreams send 11-15).
- Forwarder (src/server.zig + src/forward.zig): engine.respond takes `?*?Forward`; non-null = uchi with upstreams, a non-local query is handed back instead of REFUSED, and every answer gets RA=1. Pending upstream queries live in `pending[256]`, poller token = `slots.len + i`; one per (name, type) with up to 64 waiters (coalescing). Each attempt = new connected UDP socket (kernel-random port; connect makes the kernel filter the source) + getrandom ID; answers must match ID + question. Timeout 2 s (sweep every 100 ms while anything is pending), socket error/SERVFAIL/REFUSED/NOTIMP/FORMERR = next upstream, TC = blocking TCP exchange to the same upstream (shortcut, blocks the loop up to 2 s), none left = SERVFAIL. TCP waiters are found by slot + `gen` so a closed/reused connection is skipped. Server allocator is `smp_allocator` (page_allocator wasted a page per cache entry).
- Local forwarding smoke test needs an upstream on port 53, which macOS here refuses (EACCES): temporarily change `parse(s, 53)` in config.zig to another port, never commit it.
- src/server.zig: one `Server` on the heap (64 KiB buffers), `slots` = 2 per listener + 64 TCP connections (a 65th is closed on accept). TCP: 10 s idle timeout swept once per poll wake (1 s), 100 messages per connection, length-prefixed pipelining; a full socket buffer blocks the loop up to 1 s (`sendAll`, shortcut). UDP: one datagram per readiness event (level-triggered). `[::]` listeners are V6ONLY so `0.0.0.0` and `[::]` both bind.
- src/poll.zig: epoll (Linux) / kqueue (macOS), read interest only, token = slot index.
- Local smoke test: write annai.toml + zone in a temp dir, `zig-out/bin/annai serve`, `dig -p 5354 @127.0.0.1 ...` (5353 is mDNS on macOS). zsh: wrap dig in a function, `$D` does not word-split.

## TSIG and UPDATE (high)
- src/tsig.zig: HMAC-SHA256 only. `wire.Message.tsig_at` = offset of a trailing TSIG RR (set by `parse`); request digest = header with ID := original ID and ARCOUNT-1, `packet[12..tsig_at]`, then the variables (lowercase key name, class ANY, TTL 0, `hmac-sha256.`, time, fudge, error, other len, other); response digest = u16 len + request MAC, the response bytes before the TSIG, same variables. Order of checks: key (BADKEY) → MAC (BADSIG) → time (BADTIME); BADKEY/BADSIG answers are unsigned (MAC size 0), BADTIME is signed with the request's time and our time as 6-byte Other Data (what BIND does); all three are rcode NOTAUTH (9). MAC size != 32 is FORMERR (shortcut). The TSIG RR is appended raw by `sign` (owner uncompressed), after the OPT; `Response.finish` reserves `Status.size()` like the OPT's 11 bytes.
- Test vector: `tsig.vector` is a real packet from macOS `nsupdate` (BIND 9.10) captured with a Python UDP sink on 127.0.0.1:5354; the response MACs were computed with Python's `hmac` (recipe: /tmp is gone, redo with `socket.recvfrom` + `hmac.new(secret, hdr + body + variables, sha256)`). `dig -y hmac-sha256:hanko:<b64>` validates our signed answers (no "Couldn't verify" line) and is the cheap local oracle.
- src/update.zig: `apply` follows RFC 2136 §3 in order: zone section (FORMERR / NOTAUTH when no loaded zone has exactly that origin), prerequisites (NOTZONE, NXDOMAIN/YXDOMAIN/NXRRSET/YXRRSET, value-dependent set compare), policy (owner's first label `_acme-challenge` and type TXT, else REFUSED logged `event=update-refused key=<name> owner=<name> reason=policy|prerequisite|unsigned|uchi-mode`), prescan (class IN/ANY/NONE rules, TXT RDATA must be whole character-strings), then changes. Prerequisites may also use type ANY (name in use / not in use) on a challenge owner. The apex's own `_acme-challenge.example.org` is a valid owner.
- Overlay: flat list of (lowercase name, rdata, capped ttl, expires); add = refresh if same (name, rdata); `max_records = 1024` → SERVFAIL when full; `expire(now)` swept once per poll wake in server.zig; deletes use swapRemove (order is not stable). Queried after the static RRset of the same owner/type (TXT only), and `exists(name)` makes ancestors NODATA instead of NXDOMAIN (ADR 0004). Not per zone: with two loaded zones where one is below the other (the unit fixture), a record updated in the parent is also served when the child zone claims the name; a real soto never loads both.
- Local smoke: `nsupdate -y hmac-sha256:hanko:<b64>`; in a shell function pass `-y $K` as separate words (a quoted `"-y $K"` gives `unknown key type ' hmac-sha256'`). nsupdate prints `update failed: NOTAUTH(BADSIG)` / `(BADKEY)` / `REFUSED` and exits 2 (bind 9.20 prints `; TSIG error with server: ...` first, same `update failed:` line after); `-v` = TCP. macOS has `dig`, `nsupdate`, `python3`.
- nsupdate (9.10 and 9.20 alike) runs check-names locally on every `update add` owner: an A/AAAA under `_acme-challenge` (underscore, not a hostname) dies with `check-names failed: bad owner` + `syntax error` before anything is sent (bind 9.20.29 bin/nsupdate/nsupdate.c:2053, `dns_rdata_checkowner` → `checkowner_in_a`; TXT owners and deletes are exempt). Put `check-names off` in every nsupdate script that must reach annai; hanko (miekg/dns) performs no such check. `-o` is GSS-TSIG, not check-names.

## Nix module and tests (medium)
- systemd unit: `DynamicUser` + `CAP_NET_BIND_SERVICE`, `ExecStart = annai serve <store annai.toml>`, `restartTriggers = [ configFile ]`, `LoadCredential=tsig-<name>:<secretFile>` per update key, strict sandboxing (`SystemCallFilter=@system-service ~@privileged ~@resources`, `MemoryDenyWriteExecute`, `RestrictAddressFamilies=AF_INET AF_INET6`). If the nixosTest shows a seccomp kill, loosen the filter, nothing else.
- Flake checks: `module` renders nix/example.nix (uchi), `module-soto` renders nix/example-soto.nix (soto, CAA, key), `module-mode-mismatch` must fail; `render` in flake.nix takes the example module as its first argument.
- Resolver client: `nixosModules.resolver` (`services.annai.resolver.{enable,address,interface,domain}`) = `systemd-resolved` + a oneshot `annai-resolver.service` bound to the link's `.device` running `resolvectl dns/domain/default-route false`; search domains derived from `domain` (`<domain>`, `kekkai.<domain>`). A link manager that rewrites per-link DNS later wins. `darwinModules.resolver` (`services.annai.resolver.{enable,address,domain}`) = `/etc/resolver/<domain>` + `networking.search` (needs `networking.knownNetworkServices` in the deployment); not evaluated in the flake (nix-darwin is not an input); sanity-check with `lib.evalModules` and stub options.
- nixosTest `checks.<linux>.authoritative` (nix/test-authoritative.nix): server = example.nix zone + a `big` TXT RRset for truncation, `forwarding.upstreams = [ ]` (no Internet: REFUSED stays testable), client = dig + the resolver module on eth1.
- nixosTest `checks.<linux>.forwarding` (nix/test-forwarding.nix): soto VM (example.net + big TXT) as upstream, uchi VM (example.nix + reverse zones, upstreams = [client v4, soto v6], maxTtl 120), client VM. The client as first upstream drops the query (firewall) so every miss takes the 2 s failover: dig uses `+time=8`. Cached entries live 120 s: keep the "upstream down" subtest early. Addresses come from `nodes.<n>.networking.primaryIPAddress`/`primaryIPv6Address` (test framework assigns 192.168.1.N / 2001:db8:1::N). Never run it locally: the orchestrator does.
- nixosTest `checks.<linux>.update` (nix/test-update.nix): soto VM = example-soto.nix + `update.lifetime = 15` + a root-only `/etc/annai/hanko.key` (`hanko:<b64>`), client VM with `pkgs.dnsutils` (bind 9.20: dig + nsupdate). Subtests: soto flags/REFUSED, CAA, add over UDP (TTL cap, NODATA ancestors), add over TCP (`-v`) + single-RR delete + RRset delete, `dig -y` signed query, refusals (policy, unsigned, BADSIG, BADKEY, BADTIME via `date -s @$(( $(date +%s) + 3600 ))` on the client, then restored) checked in nsupdate's output and in `journalctl -u annai.service`, expiry after 20 s. nsupdate is driven through `client.execute("printf '...' | nsupdate -y ... 2>&1")` with `check-names off` in the script (see TSIG section) and the printed rcode is the oracle, not the exit status. First builder run (M3 attempt 1) failed only on the missing `check-names off`; `default` and `module-soto` passed.
- Type check recipe, one shell line (NP = `nix eval --inputs-from . --raw nixpkgs#path`, one `create_fake_qemu_machine()` per node of that test): `{ cat $NP/nixos/lib/test-script-prepend.py; echo 'vlan1 = create_fake_vlan()'; echo 'soto = create_fake_qemu_machine()'; echo 'client = create_fake_qemu_machine()'; nix eval --raw '.#checks.aarch64-linux.update.driver.testScript'; } > s.py && nix shell --impure --expr "with import $NP {}; [ ty ruff (python3.withPackages (p: with p; [ pydantic colorama ipython junit-xml ptpython remote-pdb typing-extensions ])) ]" -c sh -c 'ty check --python $(dirname $(dirname $(command -v python3))) --extra-search-path '$NP'/nixos/lib/test-driver/src s.py; ruff check --select F s.py'`. Pitfalls met: a test-script variable named `log` shadows the driver's logger (ty error); an f-string whose only placeholder is a Nix `${...}` becomes placeholder-less Python (ruff F541).
- Test script assertions: always `out = client.succeed(...); assert ... in out, out`, the driver logs the command but not its output. `getent hosts` is `gethostbyname2(AF_INET6)` first and prints only the IPv6 address when an AAAA exists (glibc nss/getent.c): use `getent ahostsv4`/`ahostsv6` to check a given family.
- The test driver type checks the script with `ty` (strict: `re.search(...).group()` is rejected, bind the match and `assert m, ...` first) and lints it with `ruff --select F`; one diagnostic fails the whole test before any VM boots. Reproduce on macOS without a VM: `nix eval --raw '.#checks.aarch64-linux.authoritative.driver.testScript' > s.py`, prepend `<nixpkgs>/nixos/lib/test-script-prepend.py` plus `vlan1 = create_fake_vlan()` and `<node> = create_fake_qemu_machine()` per node, then `ty check --python <python env with pydantic colorama ipython junit-xml ptpython remote-pdb typing-extensions> --extra-search-path <nixpkgs>/nixos/lib/test-driver/src s.py` (ty, ruff and the env from the pinned nixpkgs via `nix shell --impure --expr`). `nix log --store ssh-ng://...` cannot fetch the builder's logs (`getBuildLogExact` unsupported): rely on the diagnostic the orchestrator pastes.

## Open
- M2 left: round-robin upstreams (optional in ADR 0008), cache metrics (M5), TCP fallback is blocking (shortcut). M2 "done when" (a week on every host) is a deployment observation.
- M3 left: the hanko integration test (Pebble, two soto VMs) lives in hanko's repository with annai as a flake input; `checks.<linux>.update` awaits its second builder run (after the check-names fix). Truncated TSIG MACs (RFC 8945 §5.2.2.1) are FORMERR; fudge is the client's, no server-side cap; UPDATE is accepted on every listener (ADR 0006 says restricting it to the overlay listener is a later hardening); `max_records` is a constant (1024), not an option.
- M4: fuzzing of the codec and the UPDATE parser, wildcards (RFC 4592); M5: SIGHUP reload of zones and keys, metrics (dynamic record count, UPDATE refusals), Type=notify.
- Additional-section glue (A/AAAA of MX/SRV/NS targets, "DS-less NS glue" of ADR 0007 v1) and opaque unknown types (RFC 3597) in TOML have no shape yet.
- GeneralPurposeAllocator in debug builds (ADR 0001) is not wired: `page_allocator` everywhere.
