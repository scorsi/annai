# ADR-0003: Configuration and zone data

- Status: accepted
- Date: 2026-10-14

## Context

The deployment repository is fully declarative. Every other project of the author uses TOML. `dig` and resolvers speak the DNS wire protocol, not the on-disk format, so the file format is free. The human interface is the NixOS module; files are generated, rarely hand-written.

## Decision

- **TOML** for both the server configuration and zone data. One main file (`annai.toml`) referencing one TOML file per zone. The NixOS module generates all of them with `pkgs.formats.toml`.
- **TOML parser = dependency**, chosen at M0 by compatibility with the pinned Zig release (candidates: tomlz, microwave). annai needs only tables, arrays of tables, strings, integers, booleans; datetime support is irrelevant.
  - **Chosen at M0: [microwave](https://github.com/edqx/microwave) (MIT), pinned by commit in `build.zig.zon` and `build.zig.zon2json-lock`**, against Zig 0.16.0 (ADR-0001). Its own test suite passes on 0.16.0; annai uses only its dynamic `Parser.Value` tree. tomlz is unmaintained since Zig 0.13. microwave tracks Zig 0.15.2, which does not link on current macOS, and its `Populate`/`Stringify` modules do not compile on 0.17.0: the next Zig upgrade waits for microwave or replaces it (contained to `src/config.zig`). Known defect worked around: a value at end of input without a trailing newline fails to parse.
- **Fully declarative, zero persistent state.** annai never writes to disk. The only in-memory runtime state is the resolver cache (ADR-0008) and ACME TXT records (ADR-0006); both are lost on restart by design.
- **Zone file shape** (frozen at M0, this is the intent):

```toml
origin = "uchi.example.org."
ttl = 300            # default TTL
serial = 1760400000  # provided by Nix, see below

[soa]
mname = "annai.uchi.example.org."
rname = "hostmaster.example.org."
refresh = 3600
retry = 600
expire = 604800
minimum = 300        # negative-caching TTL, RFC 2308

[names."@"]
ns = ["annai.uchi.example.org."]

[names."hub.kekkai"]
a = ["10.100.0.1"]          # illustrative; kekkai's range is in 10.0.0.0/8, never Tailscale's 100.64.0.0/10
aaaa = ["fd12:3456:789a::1"]

[names."git"]
cname = "vm.kekkai"

[names."_imaps._tcp"]
srv = [{ priority = 10, weight = 0, port = 993, target = "mail.soto.example.org." }]

[names."soto"]
caa = [{ flags = 0, tag = "issue", value = "letsencrypt.org" }]   # v1 (ADR 0007), RFC 8659
```

  Keys are relative to `origin` unless they end with a dot. Record values are arrays (RRsets); `cname` is a single value and excludes other types on the same name (validated).
- **SOA serial** comes from Nix: the flake's `lastModified` of the deployment input, which is monotonic in practice. Without zone transfers (ADR-0009) the serial has no operational role beyond SOA correctness.
- **`annai check <annai.toml>`** validates the whole configuration and all zones (schema, CNAME exclusivity, SOA/NS presence, glue sanity) and exits non-zero. The NixOS module runs it in a build-time check so an invalid zone fails `nixos-rebuild`, not the running server.

## Alternatives considered

- **RFC 1035 master zone files**: free validation tooling (`named-checkzone`), portable, importable from a registrar's export. Rejected: a second, quirky grammar to parse (`$ORIGIN`, `$TTL`, parentheses, implicit owner names); no human will write these files anyway. Kept as a possible *import* subcommand later.
- **JSON** generated by Nix: zero parser cost (`std.json`). Rejected for consistency with the other projects, not on technical grounds.
- **Hand-written TOML subset parser**: good Zig exercise, no dependency. Deferred: a dependency ships faster; replacing it later is contained to one module.

## Consequences

- Reloading (ADR-0011) is a re-read of the same files and an atomic swap of the in-memory zone set.
- Anything dynamic must be justified by an ADR (so far only ADR-0006).
