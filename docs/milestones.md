# annai — milestones

Each milestone ends with a passing nixosTest (ADR-0011). Versions: v0 = internal use; v1 = public NS + ACME; v2 = comfort and hardening.

## M0 — Foundations

- Repository on Forgejo with GitHub mirror; flake with pinned Zig, zig2nix packaging, devShell, `nix flake check`.
- Spike: pick the TOML dependency against the pinned Zig (ADR-0003); record the choice in the ADR.
- Wire codec: header, names with compression, question, RR (opaque RDATA), OPT. Unit tests + malformed-packet corpus.
- `annai check` subcommand validating `annai.toml` and zone files.
- NixOS module skeleton rendering TOML from options and running `annai check` at build time.
- Done when: codec round-trips a `dig`-captured packet set; `annai check` rejects every invalid fixture.

## M1 — Authoritative core (v0.1)

- Zone loading into RRset maps; SOA/NS/A/AAAA/CNAME/TXT/PTR/SRV/MX typed RDATA.
- UDP and TCP listeners on IPv4/IPv6, single-threaded poller (ADR-0001).
- Authoritative answers: AA, NXDOMAIN + SOA, NODATA, empty non-terminals, in-zone CNAME chasing, `REFUSED` outside zones, EDNS0 payload sizing and TC truncation, `ANY` → HINFO.
- nixosTest: client `dig` suite over UDP and TCP against the `uchi.example.org` fixture.
- Deployed on one internal host serving `uchi.example.org`; the operator's workstation resolves through it (ADR-0010).
- Resolver client modules (NixOS, nix-darwin): resolver and search domains pointed at the uchi instance (ADR-0010).
- kekkai's address prefixes and per-node addresses are allocated in the deployment repository now, before kekkai runs: annai's zone data comes from them.
- Done when: two hosts resolve a `<node>.kekkai.uchi.example.org` name through annai.

## M2 — Forwarder and cache (v0.2 = v0 complete)

- `uchi` mode: upstream list with failover, UDP + TCP fallback, RFC 5452 randomisation, in-flight coalescing (ADR-0008).
- Cache: positive/negative, TTL clamps, LRU cap.
- Reverse zones for kekkai ranges generated by the module (ADR-0005).
- nixosTest: `uchi` VM forwarding to a `soto` VM; cache hit observed on the second query; TC fallback exercised with a large TXT.
- Every host sends all DNS to annai.
- Done when: annai is the only resolver used on every host for a week without incident.

## M3 — soto mode and RFC 2136 (v1.0, part 1)

- `mode = "soto"`: authoritative only, `RD` ignored, `RA=0`, no forwarding config allowed (ADR-0002).
- TSIG HMAC-SHA256 verify/sign with test vectors; RFC 2136 UPDATE parsing, prerequisites, policy (`_acme-challenge.*` TXT only), in-memory overlay with TTL/lifetime caps (ADR-0006).
- `CAA` record type.
- nixosTest: `nsupdate -k` adds and deletes a challenge; unauthorised key, wrong name, wrong type each get `REFUSED`; record expires.
- hanko integration test (in hanko's repository, annai as a flake input): hanko obtains a certificate against a Pebble ACME server using DNS-01 through annai (fan-out to two `soto` VMs).
- Done when: the Pebble test passes with two `soto` VMs. The real certificate comes with M4: hanko has no interim backend.

## M4 — Public nameservers (v1.0)

- Fuzzing campaign on the codec and UPDATE parser; fix findings. Prerequisite, not optional (ADR-0009).
- Deploy `soto` on the public entry point(s) as `ns1`/`ns2`, apex zones `example.org` and `example.net` with the current public records (`soto.*`, product CNAMEs, MX, CAA, NS, glue).
- Registrar switch: the deployment repository's checklist; annai's only constraint is no DS record (ADR-0009).
- Wildcards (RFC 4592).
- Done when: `dig +trace cv.example.org` resolves through `ns1.example.org`, and hanko has issued a production certificate for an internal name via DNS-01.

## M5 — Operations (v1.1)

- `SIGHUP` atomic reload of zones and keys; `Type=notify` readiness.
- Prometheus metrics endpoint on a loopback listener, scraped by the local agent (ADR-0011 amendment; done ahead of M5 with the JSON logs).
- `ns1` and `ns2` on two separate hosts, deployed in one run.
- Done when: `ns2` answers from a second host and the metrics are scraped.

## M6 — Hardening and privacy (v2)

- Upstream DoT (TLS 1.3 client) with fallback policy.
- Response rate limiting on `soto`.
- Optional blocklist zones in `uchi` mode.
- DNSSEC: write an ADR deciding whether to sign at all.

## Not planned

Recursion from the roots, AXFR/IXFR/NOTIFY, DoT/DoH as a server, DNS cookies, EDNS client subnet, web UI, running annai on macOS (the nix-darwin module only configures the resolver, ADR-0010).
